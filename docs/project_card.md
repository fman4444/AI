## 1. 주제

- 출발점: 주 4.5일제 근무에 대한 평가기준이 있고, 매주 부서별로 그 기준을 충족했는지 검토해야 하는 번거로움을 개선하고자 함
- 한 줄: 부서별 근무 현황을 검토하는 담당자가 · 매주 평가기준 충족 여부를 일일이 확인하는 불편을 · 부서별 충족 판정과 검수를 한곳에서 하는 여러 페이지 웹앱으로 줄인다. [가정]
- 넣을 검증 절차: ☐ 근거 대조 ☑ 계산 검산 ☑ 정합 검사 (1개 이상) [가정]
  - 계산 검산: 부서별 근무 현황을 평가기준대로 계산한 값을 사람이 손으로 센 값(두 번째 방법)과 대조한다.
  - 정합 검사: 메인·기능 페이지·검수창이 같은 부서에 같은 값과 판정을 보여 주는지 확인한다.

## 2. 범위

| 오늘 만들 것 (MVP) | 오늘 만들지 않을 것 |
|---|---|
| 기능 A 페이지 — 부서별 주간 근무 현황을 넣고 평가기준 충족 여부를 판정해 보여 준다. [가정] | 로그인·외부 연동·인쇄 양식 [가정] |
| 기능 B 페이지 — 미충족 부서와 사유를 모아 주간 검토 결과로 정리한다. [가정] | 실제 부서 자료 입력(가상 표본만 쓴다) [가정] |
| 메인 랜딩 페이지(`tools/index.html`) — 이번 주 부서별 충족 요약, 메뉴, 백업, 비우기 | 판정 확정(모든 판정은 "담당 검토 후 확정") [가정] |
| 설정 및 검수창 — 평가기준 값을 설정하고, 입력과 판정을 사람이 검수한다. 위치는 `tools/index.html` 안의 구역으로 둔다. [가정] | |

- 4.5일제 평가기준의 구체 값(기준 근무시간 등)은 자료에 없어 쓰지 않았다. {확인 필요: 4.5일제 평가기준 값}
- 설정 및 검수창을 별도 페이지로 둘지는 {확인 필요: 팀 합의}. `CLAUDE.md` 웹앱 규칙은 `index.html` + 기능 페이지 2개 구조이고, 페이지를 늘리려면 `docs/design.md` 파일 경계와 분담을 먼저 고쳐야 한다.
