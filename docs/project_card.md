# 프로젝트 카드 — 2G조

> 팀 PRD ① 블록 첫 실습 · 조원이 말하고 드라이버 세션이 채워 커밋합니다(`[팀] 프로젝트 카드`). 인터뷰 전에 정하는 것이라 거칠어도 됩니다. PRD가 나오면 1·2절만 다시 맞춥니다.
> `[가정]`은 조원이 정하지 않아 세션이 채운 내용입니다. 팀에서 확인 후 고칩니다.

## 1. 주제

- 출발점: 주 4.5일제 근무에 대한 평가기준이 있고, 매주 부서별로 그 기준을 충족했는지 검토해야 하는 번거로움을 개선하고자 함
- 한 줄: 부서원과 검토 담당자가 · 매주 근태를 모아 평가기준에 손으로 대조하는 불편을 · 근태 입력과 부서별 충족 판정을 한곳에서 하는 여러 페이지 웹앱으로 줄인다.
- 넣을 검증 절차: ☐ 근거 대조 ☑ 계산 검산 ☑ 정합 검사 (1개 이상)
  - 계산 검산: 부서별 달성자·평가대상자·충족 판정을 표본을 직접 센 기대값(두 번째 방법)과 대조한다.
  - 정합 검사: 시작 페이지 요약 숫자와 충족 현황 숫자가 같은지, 중복 입력·명단에 없는 사번·값 오류가 '확인 필요'로 따로 보이는지 확인한다.

## 2. 범위

| 오늘 만들 것 (MVP) | 오늘 만들지 않을 것 |
|---|---|
| 근태 입력 페이지(`tools/pages/IN.html`) — 부서원이 대상 금요일의 부재 유형·부재 시간을 입력 | 로그인·외부 연동·인쇄 양식·배포 |
| 충족 현황 페이지(`tools/pages/board.html`) — 개인 달성·부서 충족 판정, 미입력자, 확인 필요 | 실제 부서 자료 입력(가상 표본만 쓴다) |
| 시작 페이지(`tools/index.html`) — 요약, A/B 바로가기, 가져오기·백업·비우기 | 판정 확정(모든 판정은 "담당 검토 후 확정") |
| | 평가기준 설정·검수·확정 화면(PRD '다음 단계') |

- 평가기준(`prd/team_prd.md` 3절): 개인은 금요일 8시간 중 휴가·출장 부재가 4시간 이상이면 달성, 부서는 평가대상자(전체 − 교육대상자)의 50% 이상이 달성하면 충족.
- 처음 카드에 있던 '설정 및 검수창'은 PRD에서 다음 단계로 옮겼다. 페이지 구성은 `CLAUDE.md` 웹앱 규칙대로 시작 페이지 + 기능 페이지 2개다.

| 역할 | 이름 | 리뷰 짝 (이 사람의 PR을 승인) |

| ① 통합·화면 | 조 전체(드라이버 세션) | 생략(조 결정) |

- 조원은 3명이고, 메인 PC 한 대에서 함께 진행하므로 역할을 사람별로 나누지 않는다(조 결정). 역할 구분은 파일 담당과 커밋 머리를 정하는 데만 쓴다.
- 리뷰 짝 승인은 생략한다(조 결정). 사람 화면 확인·조원 리뷰·다른 조 교차 검증은 AI 자동 시험으로 대신한다.
- 표본 데이터 사용 승인: ④
- PRD 범위 변경: 조원 합의(서기가 `docs/team_decisions.md`에 기록)
